# Spezielle Handhabung von Eingangs- und Rückgabeparametern

## Optionale Parameter
Optionale [``Parameter``](../../../05_Glossar.md#parameter) erhöhen die Flexibilität von [``Methoden``](../../../05_Glossar.md#methode), indem sie es dem Aufrufer erlauben, bestimmte Argumente wegzulassen. Ein [``Parameter``](../../../05_Glossar.md#parameter) wird optional, indem ihm in der Methodensignatur ein Standard-[``Wert``](../../../05_Glossar.md#wert) zugewiesen wird. Alle optionalen [``Parameter``](../../../05_Glossar.md#parameter) müssen zwingend **nach** den erforderlichen (nicht-optionalen) [``Parametern``](../../../05_Glossar.md#parameter) definiert werden.

Man kann optionale [``Parameter``](../../../05_Glossar.md#parameter) weglassen, positionell angeben oder über ihren Namen ansprechen. Die Kombination mit benannten Argumenten ist besonders mächtig, da man so spezifische optionale [``Parameter``](../../../05_Glossar.md#parameter) überschreiben kann, ohne die davorliegenden ebenfalls angeben zu müssen.

```csharp
// 'subject' und 'isHighPriority' sind optionale Parameter
public void SendEmail(string recipient, string body, string subject = "No Subject", bool isHighPriority = false)
{
    Console.WriteLine($"Sending to: {recipient}");
    Console.WriteLine($"Subject: {subject}");
    Console.WriteLine($"Body: {body}");
    Console.WriteLine($"High Priority: {isHighPriority}");
    Console.WriteLine("---");
}

// 1. Aufruf nur mit den erforderlichen Parametern
// 'subject' und 'isHighPriority' nehmen ihre Standardwerte an.
SendEmail("test@example.com", "This is the body.");

// 2. Aufruf mit einem optionalen Parameter (positionell)
// 'subject' wird überschrieben, 'isHighPriority' bleibt Standard.
SendEmail("test@example.com", "Another body.", "Important Update");
```

>**Wir merken uns:**
>1) **Optionale [``Parameter``](../../../05_Glossar.md#parameter)** benötigen einen Standard-[``Wert``](../../../05_Glossar.md#wert) und müssen am Ende der Methodensignatur stehen. Sie können beim Aufruf weggelassen werden.

## Named vs. Positional Arguments
[``Parameter``](../../../05_Glossar.md#parameter) können an [``Methoden``](../../../05_Glossar.md#methode) auf zwei Arten übergeben werden: über ihre Position oder über ihren Namen.

*   **Positional Arguments (Positionsbezogen):** Dies ist die Standardmethode. Die Argumente müssen in der exakten Reihenfolge übergeben werden, in der die [``Parameter``](../../../05_Glossar.md#parameter) in der Methodensignatur definiert sind. Dies ist bei [``Methoden``](../../../05_Glossar.md#methode) mit wenigen, eindeutigen [``Parametern``](../../../05_Glossar.md#parameter) unproblematisch. Bei [``Methoden``](../../../05_Glossar.md#methode) mit vielen [``Parametern``](../../../05_Glossar.md#parameter) wird es schnell unleserlich und fehleranfällig.
*   **Named Arguments (Benannt):** Hier wird der Name des [``Parameters``](../../../05_Glossar.md#parameter) explizit angegeben, gefolgt von einem Doppelpunkt und dem [``Wert``](../../../05_Glossar.md#wert) (`parameterName: value`). Dies erhöht die Lesbarkeit des Codes erheblich, da die Absicht jedes Arguments sofort klar ist. Ein weiterer Vorteil ist, dass die Reihenfolge der Argumente irrelevant wird. 

```csharp
// Eine Methode mit vielen, teils optionalen, Parametern
public void GenerateReport(string reportName, bool includeHeader, bool includeFooter, string author = "System", int resolutionDpi = 300)
{
    Console.WriteLine($"Generating Report: '{reportName}'");
    Console.WriteLine($"Author: {author}, Resolution: {resolutionDpi} DPI");
    Console.WriteLine($"Header included: {includeHeader}, Footer included: {includeFooter}");
}

// 1. Aufruf mit Positional Arguments
// Unübersichtlich: Was bedeuten 'true, true'? Man muss die Methodendefinition nachschlagen.
GenerateReport("MonthlySales", true, true, "John Doe");

// 2. Aufruf mit Named Arguments
// Viel klarer und selbst-dokumentierend. Die Reihenfolge ist hierbei egal.
GenerateReport(
    includeFooter: true, 
    reportName: "AnnualReview", 
    includeHeader: true, 
    resolutionDpi: 600
); 
// Der optionale 'author' Parameter wird weggelassen.
```

>**Wir merken uns:**
>2) **Named Arguments** (`parameterName: wert`) machen Methodenaufrufe extrem lesbar und erlauben es, die Reihenfolge der übergebenen Argumente zu ignorieren.

## Das `params` Keyword
Das [``Schlüsselwort``](../../../05_Glossar.md#schlüsselwort) **`params`** ermöglicht es einer [``Methode``](../../../05_Glossar.md#methode), eine variable Anzahl von Argumenten desselben [``Typs``](../../../05_Glossar.md#typ) zu akzeptieren. Es erspart dem Aufrufer, explizit ein [``Array``](../../../05_Glossar.md#array) erstellen zu müssen. Andere Collections funktionieren hier nicht direkt, es muss ein [``Array``](../../../05_Glossar.md#array) sein.

**Wichtige Regeln:**
1.  Es kann nur **ein** **`params`**-``Parameter`` pro [``Methode``](../../../05_Glossar.md#methode) geben.
2.  Der **`params`**-``Parameter`` muss zwingend der **letzte** [``Parameter``](../../../05_Glossar.md#parameter) in der Methodensignatur sein.

```csharp
public void LogEntries(string category, params string[] messages)
{
    Console.WriteLine($"--- Log Category: {category} ---");
    
    if (messages.Length == 0)
    {
        Console.WriteLine("No messages provided.");
        return;
    }

    for (int i = 0; i < messages.Length; i++)
    {
        Console.WriteLine($"Message {i + 1}: {messages[i]}");
    }
}

// Verschiedene Aufrufe:
LogEntries("ERROR", "Database connection failed.", "Retrying in 5 seconds.");
LogEntries("INFO", "User logged in successfully.");
LogEntries("WARN"); // Auch ein Aufruf komplett ohne params-Argumente ist gültig (leeres Array).
```

>**Wir merken uns:**
>3) Das [``Schlüsselwort``](../../../05_Glossar.md#schlüsselwort) **`params`** erlaubt die Übergabe einer variablen Anzahl von Argumenten gleichen [``Typs``](../../../05_Glossar.md#typ). Es erzeugt im Hintergrund ein [``Array``](../../../05_Glossar.md#array) und muss der letzte [``Parameter``](../../../05_Glossar.md#parameter) sein.

## Rückgabeparameter aufteilen mit Tuples
Vor C# 7.0 war die Rückgabe mehrerer [``Werte``](../../../05_Glossar.md#wert) aus einer [``Methode``](../../../05_Glossar.md#methode) umständlich (meist über **`out`**-Parameter oder das unhandliche `System.Tuple`).
**ValueTuples** lösen dieses Problem elegant. Sie sind leichtgewichtige Datenstrukturen (`structs`), die es erlauben, mehrere (sogar benannte) Elemente auf einmal zurückzugeben.

### Tuple anlegen
Ein Tuple wird mit runden Klammern definiert:
```csharp
// Unbenanntes Tuple (Zugriff später über Item1, Item2, Item3)
var meinUnbekanntesTuple = (1, "ok", 563);

// Benanntes Tuple (Bessere Lesbarkeit, Zugriff über id, status, anzahl)
var meinBekanntesTuple = (id: 1, status: "ok", anzahl: 563);
Console.WriteLine(meinBekanntesTuple.status); // Gibt "ok" aus
```

### Out Keyword vs. Tuples
Das [``Schlüsselwort``](../../../05_Glossar.md#schlüsselwort) **`out`** übergibt [``Parameter``](../../../05_Glossar.md#parameter) als *Call by Reference*. Es zwingt die Methode, die Variablen mit einem Wert zu füllen.

```csharp
// 1. Klassischer Ansatz mit 'out'
public bool TryParseCoordinates(string input, out double latitude, out double longitude)
{
    latitude = 0;
    longitude = 0;
    string[] parts = input.Split(',');
    if (parts.Length != 2) return false;
    
    bool latParsed = double.TryParse(parts[0], out latitude);
    bool lonParsed = double.TryParse(parts[1], out longitude);
    
    return latParsed && lonParsed;
}

// 2. Moderner Ansatz mit einem benannten Tuple als Rückgabetyp
public (bool success, double latitude, double longitude) ParseCoordinates(string input)
{
    string[] parts = input.Split(',');
    if (parts.Length != 2) return (false, 0, 0); 

    bool latParsed = double.TryParse(parts[0], out var lat);
    bool lonParsed = double.TryParse(parts[1], out var lon);

    if (latParsed && lonParsed) return (true, lat, lon); 
    
    return (false, 0, 0); 
}
```

### Aufruf und "Deconstruction" des Tuples
Der große Vorteil von Tuples zeigt sich beim Aufruf der [``Methode``](../../../05_Glossar.md#methode). Wir können das zurückgegebene Tuple entweder in einer [``Variablen``](../../../05_Glossar.md#variable) speichern oder es sofort in seine Einzelteile zerlegen (Deconstruction).

```csharp
// Variante A: Zuweisung in eine einzige Tuple-Variable
var tuple = ParseCoordinates("48.2082, 16.3738");

// Variante B: Deconstruction (Aufteilen) des Rückgabeparameters
// Wir definieren in den runden Klammern sofort drei neue, eigenständige Variablen.
var (wasSuccessful, lat, lon) = ParseCoordinates("48.2082, 16.3738");

if (wasSuccessful)
{
    Console.WriteLine($"Latitude: {lat}, Longitude: {lon}");
}
```

>**Wir merken uns zu Tuples und Out:**
>4) **Tuples** (z. B. `(int id, string name)`) sind die modernste und sauberste Methode in C#, um mehrere [``Werte``](../../../05_Glossar.md#wert) gleichzeitig aus einer [``Methode``](../../../05_Glossar.md#methode) zurückzugeben, ohne komplexe [``Klassen``](../../../05_Glossar.md#klasse) oder **`out`**-[``Parameter``](../../../05_Glossar.md#parameter) nutzen zu müssen.
>5) Durch **Deconstruction** (`var (erfolg, x, y) = Methode()`) kann ein zurückgegebenes Tuple beim Aufruf direkt in einzelne [``Variablen``](../../../05_Glossar.md#variable) aufgespalten werden.
>6) Das [``Schlüsselwort``](../../../05_Glossar.md#schlüsselwort) **`out`** erlaubt es, einer [``Methode``](../../../05_Glossar.md#methode) eine [``Variable``](../../../05_Glossar.md#variable) als Referenz mitzugeben, welche die Methode dann zwingend mit einem [``Wert``](../../../05_Glossar.md#wert) füllen muss. Dies wird häufig in `TryParse`-[``Methoden``](../../../05_Glossar.md#methode) angewendet.
