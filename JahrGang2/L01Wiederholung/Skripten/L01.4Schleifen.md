# 1. Codewiederholung mit der While-Schleife

Wir haben bisher Code nur linear ausgeführt. Aber was ist, wenn wir etwas wiederholen müssen?
Das vierte große Werkzeug in der Programmierung sind ``Schleifen``. 

## Warum Schleifen?
Schauen wir uns folgenden Code an:
```csharp
Console.WriteLine("🙂");
Console.WriteLine("🙂");
Console.WriteLine("🙂");
```
Dieser wiederholt die Ausgabe. Wie oft soll das geschehen, wenn wir die Anzahl der Wiederholungen erst zur Laufzeit durch den User erfahren? Ohne ``Schleifen`` müssten wir eine unendlich lange ``Mehrfachverzweigung`` schreiben.

> Ohne ``Schleifen`` müssten wir für die Lösung mancher Probleme unendlich lange ``Programme`` schreiben, was unmöglich ist.

## Die While-Schleife
Die *allgemeinste* Form der ``Schleife`` ist die ``While-Schleife``. Sie wiederholt den Code ihres ``Blocks`` so lange, bis eine ``logische Bedingung`` *false* ergibt.

```csharp
int i = 0; // Zählvariable

while (i < 5) 
{ 
    Console.WriteLine("🙂");
    i = i + 1; // Inkrement der Zählvariable
}
```

Wir merken uns:
> Eine ``While-Schleife`` betritt den ``Block`` nur, wenn die ``Bedingung`` (vor dem Ausführen) *wahr* ist.
> Wenn wir eine ``Zählvariable`` verwenden, zählen wir mit, wie oft die ``Schleife`` ausgeführt wurde. 
> Ein Hochzählen (`i = i + 1`) nennt man ``Inkrement``. Ein Herunterzählen (`i = i - 1`) nennt man ``Dekrement``.

### Zählweisen
Ob wir von 0 bis 4 hochzählen oder von 5 bis 1 herunterzählen, ändert nichts daran, dass die ``Schleife`` exakt 5-mal ausgeführt wird. Die Richtung (Inkrement oder Dekrement) wird oft abhängig davon gewählt, was wir innerhalb der ``Schleife`` mit der Zahl tun wollen (z. B. Muster zeichnen).

### Wenn die Schleife (theoretisch) unendlich oft ausgeführt werden kann
Oft wissen wir vorher nicht, wie oft eine ``Schleife`` laufen muss – etwa bei der Eingabeüberprüfung. Wir fragen den User so lange nach seinem Alter, bis er eine gültige Zahl eingibt.

```csharp
Console.Write("Bitte Alter eingeben (18-120): ");
int alter = int.Parse(Console.ReadLine());

while (alter < 18 || alter > 120) 
{
    Console.Write("Ungültig. Bitte korrektes Alter eingeben: ");
    alter = int.Parse(Console.ReadLine());
}
```
Hier ist völlig unklar, ob der User beim ersten Versuch eine korrekte Zahl eingibt oder erst beim zehnten. Genau hier glänzt die ``While-Schleife``.

### break und continue
Manchmal wollen wir aus einer Schleife ausbrechen, ohne dass die `while`-Bedingung geprüft wird.

*   **`break`**: Bricht die komplette ``Schleife`` sofort ab.
*   **`continue`**: Bricht nur den *aktuellen Durchlauf* ab und springt sofort wieder nach oben zur Prüfung der ``Bedingung``.

```csharp
while (true) // Theoretisch unendliche Schleife
{
    Console.Write("Gib ein sicheres Passwort ein: ");
    string passwort = Console.ReadLine();

    if (passwort.Length < 8) 
    {
        Console.WriteLine("❌ Zu kurz!");
        continue; // Bricht hier ab, startet die Schleife von neuem
    }

    if (passwort == "12345678") 
    {
        Console.WriteLine("❌ Zu unsicher!");
        continue;
    }

    Console.WriteLine("✅ Passwort akzeptiert!");
    break; // Bricht die Schleife endgültig ab!
}
```

Wir merken uns:
> Wir springen aus dem ``Block`` einer ``Schleife`` mit dem Keyword **`break`**.
> Wir nutzen **`continue`** oder **`break`** oft in Kombination mit einer ``Guard Clause``, um Fehler abzufangen und den Haupt-Code übersichtlich zu halten.

## Die Do-While-Schleife
Ein kleines strukturelles Problem der klassischen ``While-Schleife`` (kopfgesteuert) ist, dass wir manchmal Code doppelt schreiben müssen (einmal *vor* der Schleife, um die Variable zu initialisieren, und einmal *in* der Schleife). 

Wenn wir sicher sind, dass der Code im Schleifen-Block **mindestens einmal** ausgeführt werden muss, verwenden wir die **``Do-While-Schleife``** (fußgesteuert).

Hier wird die ``Bedingung`` erst am *Ende* geprüft:

```csharp
Random random = new Random();
int draw = random.Next(1, 101); // Zahl zwischen 1 und 100
int versuch;
int trials = 0;

Console.WriteLine("Rate eine Zahl zwischen 1 und 100");

// Game Loop: Wird garantiert mindestens 1x ausgeführt!
do 
{
    Console.Write("Dein Tipp: ");
    versuch = int.Parse(Console.ReadLine());

    if (versuch < draw) 
    {
        Console.WriteLine("Inkorrekt! - Zahl ist zu klein.");
    } 
    else if (versuch > draw) 
    {
        Console.WriteLine("Inkorrekt! - Zahl ist zu groß.");
    } 
    else 
    {
        Console.WriteLine($"Richtig! Du hast {trials + 1} Versuche gebraucht.");
        break; // Verlässt die Schleife beim Sieg
    }

    trials++;

} while (true); // Theoretisch ginge hier auch: while (versuch != draw);
```

Wir merken uns:
> Wir verwenden eine ``Do-While-Schleife``, wenn der enthaltene Code **mindestens ein einziges Mal** ausgeführt werden muss, unabhängig davon, wie die ``Bedingung`` danach ausfällt.

# 2. Codewiederholung mit einer Zählschleife-Schleife
Wir kennen bereits die ``While-Schleife``. Wir erinnern uns: Wenn eine ``Schleife`` theoretisch unendlich oft laufen kann (z. B. Warten auf eine korrekte Usereingabe), ist die `while`-Schleife das richtige Werkzeug. 

Wenn wir jedoch vorab genau wissen, wie oft eine ``Schleife`` laufen soll – also **endlich viele ($n<\infty$) Wiederholungen** haben –, verwenden wir stattdessen die **``For-Schleife``**. 

> **Wichtig:** Wir verwenden eine `while`-Schleife **niemals** als reine Zählschleife, wenn wir stattdessen eine `for`-Schleife nutzen können!

---


## Warum eine For-Schleife?
Folgendes ändert sich nicht: Eine ``Schleife`` hat den Sinn, einen ``Block`` zu wiederholen, und zwar so lange, bis eine ``Bedingung`` nicht mehr erfüllt ist. 

Die ``For-Schleife`` ist insofern "spezieller", als dass sie den Programmierer dazu zwingt, die gesamte Logik der ``Zählvariablen`` an einem einzigen Ort zu bündeln: im sogenannten ``Schleifenkopf``.

Vergleichen wir eine als Zählschleife missbrauchte `while`-Schleife mit einer echten `for`-Schleife:

```csharp
// SCHLECHT: Die Zähllogik ist über den ganzen Code verstreut
int zaehlvariable = 0; // 1. Definition

while (zaehlvariable < 10) // 2. Bedingung
{
    Console.WriteLine("WHILE: Code ausgeführt.");
    zaehlvariable++; // 3. Inkrement (ganz am Ende versteckt)
}
```

```csharp
// GUT: Alles ist kompakt im Schleifenkopf vereint
for (int i = 0; i < 10; i++) 
{
    Console.WriteLine("FOR: Code ausgeführt.");
}
```

Wir merken uns:
> Die ``For-Schleife`` zwingt den Programmierer, die Deklaration der ``Zählvariable``, die ``Bedingung`` und das ``Inkrement``/``Dekrement`` übersichtlich im ``Schleifenkopf`` zu schreiben. 
> Wir trennen diese drei Bereiche innerhalb des ``Schleifenkopfs`` mit einem Semikolon `;`.

Betrachten wir die ``Syntax`` der ``For-Schleife`` genauer:  
**`for (Bereich1; Bereich2; Bereich3) { ... }`**

*   **Bereich 1 (Initialisierung):**
    Hier wird die ``Zählvariable`` definiert und initialisiert (meist `int i = 0;`). Sie existiert nur für die Dauer dieser ``Schleife`` (das ist ihr ``Scope``).
*   **Bereich 2 (Bedingung):**
    Ein ``Ausdruck``, der die ``Bedingung`` darstellt (z. B. `i < 10`). Solange diese auf *true* auswertet, wird der ``Block`` wiederholt.
*   **Bereich 3 (Aktion/Inkrement):**
    Eine ``Anweisung``, die am Ende jedes Schleifendurchlaufs ausgeführt wird. Meistens ist das die Erhöhung der Zählvariablen (z. B. `i++`).

*(Anmerkung: Theoretisch können diese Bereiche leer gelassen oder mit wilden Anweisungen wie Methodenaufrufen gefüllt werden. In der Praxis tun wir das jedoch nie, um den Code lesbar zu halten.)*

## Es gilt alles, was wir von der While-Schleife kennen... deshalb ein paar Beispiele

Wie auch bei der `while`-Schleife können wir `break` und `continue` nutzen, um den Ablauf innerhalb des ``Blocks`` zu steuern. Die `for`-Schleife eignet sich besonders, um bekannte Längen oder Muster abzuarbeiten.

### Beispiel 1: Einen String Zeichen für Zeichen auslesen
Jeder ``String`` hat eine bestimmte Länge (`.Length`). Diese eignet sich perfekt als obere Grenze für unsere ``Bedingung``.

```csharp
string myString = "Hallo Welt";

// Wir zählen von Index 0 bis zum letzten Zeichen des Strings
for (int i = 0; i < myString.Length; i++) 
{
    // Greife auf das einzelne Zeichen an der Position 'i' zu
    Console.WriteLine(myString[i]);
}
```

### Beispiel 2: Formen zeichnen (Verschachtelte For-Schleifen)
Wir können `for`-Schleifen schachteln (eine Schleife in einer Schleife), um zweidimensionale Muster zu erzeugen. Die äußere ``Schleife`` steuert die Zeilen (Y-Achse), die innere ``Schleife`` steuert die Spalten (X-Achse).

**Aufgabe:** Gib folgendes Muster mithilfe von Schleifen in der Konsole aus:

```
⬜
⬜⬜
⬜⬜⬜
⬜⬜⬜⬜
⬜⬜⬜⬜⬜
```

**Lösung:**
```csharp
int oberesLimit = 5; // Wie viele Zeilen wollen wir zeichnen?

for (int zeile = 1; zeile <= oberesLimit; zeile++) 
{
    // Die innere Schleife läuft so oft, wie die aktuelle 'zeile' groß ist.
    // In Zeile 1 läuft sie 1 mal. In Zeile 3 läuft sie 3 mal.
    for (int spalte = 1; spalte <= zeile; spalte++) 
    {
        Console.Write("⬜"); // Console.Write macht KEINEN Zeilenumbruch
    }
    
    // Nach jeder komplett gezeichneten Zeile machen wir einen Umbruch
    Console.WriteLine(); 
}
```
