# 1. Verzweigungen und Bedingte Anweisungen mit If

## Was ist unser Ziel mit diesem Werkzeug?
Stellen wir uns folgendes Problem vor: Wir haben eine Kontrolle einer Person bei einem Onlinevertragsabschluss und fragen ab, ob diese *alt genug* ist und einen *Führerschein* hat, um ein Auto zu kaufen. Falls sie alt genug ist und einen Führerschein hat, befinden wir uns in einem Zustand, welcher uns erlaubt, den Kunden positiv abzuspeichern. Um dies umzusetzen, brauchen wir ``Verzweigungen`` bzw. ``Bedingte Anweisungen``. Diese steuern, welcher Programmcode ausgeführt wird. Solche Konstrukte werden ``Kontrollstrukturen`` genannt. Die Grundlage für eine solche Steuerung sind ``logische Formeln``, welche wir bereits kennengelernt haben. Diese bestehen aus booleschen Werten, welche mit ``logischen Operatoren`` bzw. ``Vergleichsoperatoren`` verknüpft werden. 

Wir merken uns:
> Eine ``Kontrollstruktur`` steuert den Ablauf eines Programms.

> Eine ``Bedingung`` ist eine ``logische Formel``, welche in einer ``Kontrollstruktur`` verwendet wird.

## Was ist eine Bedingte Anweisung (Conditional)?
Schreiben wir folgenden Code, welcher die Kontrolle einer Person darstellt:

```csharp
Console.Write("Wie alt sind Sie? ");
int alter = int.Parse(Console.ReadLine()); // Usereingabe aus der Console lesen

if (alter >= 18) 
{
    Console.WriteLine("Verstehe. Sie sind alt genug.");
}
```

Wir sehen hier: Die Ausgabe *Verstehe. Sie sind alt genug.* wird nur ausgegeben, wenn das *alter* größer oder gleich *18* ist. Diese Ausgabe ist also ``bedingt`` durch die ``logische Formel`` *alter >= 18*, welche wir ``Bedingung`` nennen. Die Ausgabe *Wie alt sind Sie?* hat keine ``Bedingung`` und ist dadurch bedingungslos. Das bedeutet, diese wird *immer* ausgeführt. 

Wir merken uns:
> Eine ``Bedingte Anweisung`` ist eine ``Kontrollstruktur``, welche uns erlaubt, Code auszuführen, wenn eine ``Bedingung`` erfüllt ist.

### Wann verwenden wir eine Bedingte Anweisung?
Wir merken uns:
> Wir modellieren mit einer ``Bedingten Anweisung`` *Wenn-dann Aussagen*. 

Wir dürfen diese also nur verwenden, wenn kein *alternatives* Verhalten angegeben wird. 

Ein Beispiel:
```csharp
// WENN ich alt genug bin, 
if (alter >= 18) 
{
    // DANN darf ich weiter.
    Console.WriteLine("Verstehe. Sie sind alt genug.");
}
// ANSONSTEN... ?
```

Wir wissen nicht, was ansonsten passiert. Wir gehen in den ``Block``, wenn dessen ``Bedingung`` erfüllt ist, und springen darüber hinweg, wenn nicht, denn wir haben keine Vorgabe, was passieren soll, wenn wir **nicht** *alt genug* sind.

### Warum erkennen wir nicht alle Variablen?
Da wir mit den geschwungenen Klammern `{}` einen neuen sogenannten ``Scope`` (oder ``Block``) einführen, müssen wir auf folgendes aufpassen, wenn wir mehrere dieser ``Bedingten Anweisungen`` untereinanderschreiben.

Hier passiert ein Fehler... jedoch welcher?
```csharp
static void Main(string[] args) 
{   // geschwungene Klammern!
    int alter = 20; // Diese Variable gibt es innerhalb der Methode

    if (alter >= 18) 
    {                           // geschwungene Klammern!
        int meinAlter = 21;     // Diese Variable gibt es nur in dieser bedingten Anweisung!
        Console.WriteLine("Verstehe. Sie sind alt genug. Ich selbst bin " + meinAlter);
    }                           // geschwungene Klammern!

    if (alter >= 95) 
    {                           // geschwungene Klammern!
        // FEHLER: 'meinAlter' existiert hier nicht!
        Console.WriteLine("Jedoch wollen Sie noch Autofahren? Ich selbst bin " + meinAlter); 
    }                           // geschwungene Klammern!
}   // geschwungene Klammern!
```

Wir sehen, die ``Variable`` *meinAlter* existiert nur innerhalb des ersten `if`-Blocks. Wir versuchen es aber innerhalb von `if (alter >= 95) { ... }` zu verwenden. Dort erkennt C# diese ``Variable`` nicht und verhindert die Kompilierung. 

Wir erkennen zusätzlich: Die ``Variable`` *alter* kann in beiden `if`-Blöcken verwendet werden. Es ist also möglich, ``Variablen`` *außerhalb* eines ``Blocks`` zu deklarieren und diese *innerhalb* zu verwenden. Umgekehrt ist es jedoch nicht möglich. 

Allgemein wird dies als ``Scope`` (Gültigkeitsbereich) einer ``Variablen`` bezeichnet. Dieser klärt, wo welche Variable erkannt wird. Wenn der Zugriff auf eine Variable *außerhalb* dieses ``Scopes`` stattfindet, nennt man dies *out of scope*.

> Der ``Scope`` wird in C# durch geschwungene Klammern `{` und `}` gekennzeichnet. ``Variablen`` können nur innerhalb dieses ``Scopes`` (und darin verschachtelter Blöcke) verwendet werden.

**Anmerkung:** Das Konzept des ``Scopes`` ist unabhängig von ``Bedingten Anweisungen``. Es wird **immer** durch `{...}` definiert, egal ob **`if`**, **`while`**, **`for`** oder einfach nur ein leerer Block vorliegt.

## Was ist eine Verzweigung (Branch)?
Eine ``Verzweigung`` liegt vor, wenn wir zu einer ``Bedingten Anweisung`` zusätzlich das *Gegenteil* der ``Bedingung`` hinzufügen.

```csharp
Console.Write("Wie alt sind Sie? ");
int alter = int.Parse(Console.ReadLine()); 

if (alter >= 18) 
{
    Console.WriteLine("Verstehe. Sie sind alt genug.");
} 
else // Was ist das Gegenteil von alter >= 18 ? (alter < 18)
{ 
    Console.WriteLine("Verstehe. Sie sind NICHT alt genug.");
}
```

Wir stellen uns 2 Türen vor, von denen wir nur eine betreten können. Wir erzeugen durch die Anwendung von **`else`** zwei ``Zweige``.

Wir merken uns:
> Wir nennen eine ``Kontrollstruktur``, welche keinen Wert zurückgibt, eine ``If-Anweisung``.
> Wir nennen eine ``If-Anweisung`` eine **``Bedingte Anweisung``**, wenn diese *kein* **`else`** hat.
> Wir nennen eine ``If-Anweisung`` eine **``Verzweigung``**, wenn diese *ein* **`else`** hat.

Wir können in den Code eines ``Zweigs`` auch eine neue ``Verzweigung`` schreiben (Schachtelung). 

```csharp
if (alter >= 18) 
{
    Console.WriteLine("Verstehe. Sie sind alt genug.");
    
    if (hatFuehrerschein) 
    {
        Console.WriteLine("Verstehe. Sie haben einen Führerschein.");
    } 
    else 
    {
        Console.WriteLine("Verstehe. Sie haben KEINEN Führerschein.");
    }
} 
else 
{ 
    Console.WriteLine("Verstehe. Sie sind NICHT alt genug.");
}
```

Wir merken uns:
> Eine ``Verzweigung`` ist ``verschachtelt``, wenn eine *weitere* ``Verzweigung`` innerhalb eines ``Zweigs`` steht.

### Wann verwenden wir eine verschachtelte Verzweigung?
Eine Schachtelung repräsentiert eine kombinierte Logik. Wir erkennen, dass die Schachtelung im obigen Beispiel dem ``logischen ODER`` / ``UND`` ähnelt: *Wenn ich älter bin als 18 UND ich einen Führerschein habe...*

> Eine geschachtelte ``Verzweigung`` in einem `if`-Zweig ist oft vergleichbar mit einem ``logischen UND`` (`&&`). 

#### Wie entsteht eine Verschachtelung?
Oft bauen wir Verschachtelungen, um sogenannte *Fehlerzustände* auszufiltern, bevor wir die eigentliche Logik (Business Logic) ausführen.

```csharp
// Überprüfe zuerst auf Fehler (Länge muss 1 sein, muss ein Buchstabe sein)
if (char.IsLetter(userCharInput) && userInput.Length == 1) 
{
    // Hier ist der gewünschte Zustand eingetreten (Business Logic)
    if (userCharInput == 'a' || userCharInput == 'e' || userCharInput == 'i' ||
        userCharInput == 'o' || userCharInput == 'u') 
    {
        Console.WriteLine("Usereingabe ist ein Vokal.");
    } 
    else 
    {
        Console.WriteLine("Usereingabe ist ein Konsonant.");
    }
} 
else 
{
    // Hier ist der ungewünschte Fehlerzustand eingetreten
    Console.WriteLine("Fehlerhafte Eingabe.");
}
```

### Wann verwenden wir eine Mehrfachverzweigung?
Wenn wir mehr als 2 Optionen (Türen) haben, nutzen wir eine ``Mehrfachverzweigung`` mit dem **`else if`** Konstrukt.

```csharp
int bewertungInProzent = 62;

if (0 <= bewertungInProzent && bewertungInProzent < 50) 
{
    Console.WriteLine("Nicht Genügend");
} 
else if (50 <= bewertungInProzent && bewertungInProzent < 62) 
{
    Console.WriteLine("Genügend");
} 
else if (62 <= bewertungInProzent && bewertungInProzent < 75) 
{
    Console.WriteLine("Befriedigend");
} 
else if (75 <= bewertungInProzent && bewertungInProzent < 87) 
{
    Console.WriteLine("Gut");
} 
else if (87 <= bewertungInProzent && bewertungInProzent <= 100) 
{
    Console.WriteLine("Sehr Gut");
} 
else 
{
    Console.WriteLine("Außerhalb der Grenzen");
}
```

Wir merken uns:
> ``Mehrfachverzweigungen`` werden verwendet, um genau **einen** von mehreren möglichen ``Zweigen`` auszuwählen.

## Was ist eine If-Anweisung (If-Statement) und was ein If-Ausdruck (If-Expression)?

Wir merken uns den essenziellen Unterschied:
> Eine **``If-Anweisung``** (If/Else Block) produziert **keinen** ``Wert``. Sie steuert nur den Ablauf.
> Ein **``If-Ausdruck``** produziert exakt **einen** ``Wert``. 

In C# existiert der ``If-Ausdruck`` in Form des ``Tertiären Operators`` (`?:`). Er verlangt drei Parameter: Bedingung, Wert für True, Wert für False.

```csharp
// Zuweisung = (Bedingung) ? WertWennWahr : WertWennFalsch;
string antwort = alter >= 18 ? "Sie sind alt genug." : "Vertrag abgelehnt.";
```

### Wann verwenden wir If-Ausdrücke?
> Wenn eine ``Variable`` in Abhängigkeit einer ``Bedingung`` direkt zugewiesen (initialisiert) wird, verwenden wir ``If-Ausdrücke`` (den `?:`-Operator).

``If-Ausdrücke`` können geschachtelt werden, jedoch wird das schnell unleserlich. Mit guter Formatierung kann es so aussehen:

```csharp
string note =   
    87 <= prozent && prozent <= 100 ? "Sehr Gut" :
    75 <= prozent && prozent < 87   ? "Gut" :
    62 <= prozent && prozent < 75   ? "Befriedigend" :
    50 <= prozent && prozent < 62   ? "Genügend" :
    0  <= prozent && prozent < 50   ? "Nicht Genügend" :
                                      "Außerhalb der Grenzen";
                                      
Console.WriteLine(note);
```

# 2. Mehrfachverzweigungen mit Switch-Anweisungen und Switch-Ausdrücken

Neben dem `if` bietet C# ein weiteres Werkzeug für ``Mehrfachverzweigungen``: Das **`switch`**. 
Mit der Weiterentwicklung von C# haben wir heute zwei Varianten: Die klassische ``Switch-Anweisung`` und den modernen ``Switch-Ausdruck`` (Switch Expression).

## Wie schreibe ich eine Verzweigung als Switch-Ausdruck?
C# (seit Version 8) bietet eine extrem kompakte Schreibweise, wenn wir basierend auf einem ``Wert`` direkt einen neuen ``Wert`` generieren wollen.

```csharp
int variable = 5;

// Moderne Switch Expression in C#
string ergebnis = variable switch 
{
    1 => "Die Variable hat den Wert eins",
    2 or 5 => "Die Variable hat den Wert zwei oder fünf.",
    _ => "Die Variable hat nicht den Wert 1, 2 oder 5." // Der _ (Unterstrich) ist das "default"
};

Console.WriteLine(ergebnis); 
```

Hier bemerken wir folgendes:
> Ein ``Switch-Ausdruck`` vergleicht eine ``Variable`` auf einen konkreten ``Wert``.
> Ist ein Vergleich erfolgreich, wird der zugewiesene ``Wert`` zurückgegeben.
> Der Unterstrich `_` fängt alle Fälle ab, die nicht explizit genannt wurden (Fallback).

Ein ``logisches ODER`` setzen wir in C# ganz einfach mit dem Keyword **`or`** (oder bei Switch-Anweisungen mit Komma bzw. untereinander) um.

### Brauche ich immer eine Rückgabe? - Die Switch-Anweisung
Nein. Wenn wir keinen ``Wert`` zurückgeben, sondern pro Fall (*case*) echten Code ausführen wollen, nutzen wir die klassische ``Switch-Anweisung``.

```csharp
int variable = 5;

switch (variable) 
{
    case 1:
        Console.WriteLine("Wert eins");
        break; // break ist zwingend erforderlich!
    case 2:
    case 5: // So setzen wir hier ein logisches ODER um
        Console.WriteLine("Wert zwei oder fünf");
        break;
    default:
        Console.WriteLine("Anderer Wert");
        break;
}
```

### Kann ich auch mehrzeilige Switch-Ausdrücke schreiben?
**In C# ist die Antwort hier NEIN.** 
Ein ``Switch-Ausdruck`` (mit `=>`) muss auf der rechten Seite exakt *einen* einzigen ``Wert`` oder *einen* Aufruf produzieren. Es ist nicht möglich, wie in Java mit geschweiften Klammern und einem `yield`-ähnlichen Konstrukt komplexe mehrzeilige Blöcke innerhalb der Expression zu schreiben. 

Wenn du mehrere Zeilen Code pro *case* benötigst (z.B. Updates auf Datenbanken, Logs schreiben), **musst** du zwingend die klassische ``Switch-Anweisung`` (mit `case:` und `break;`) nutzen oder die komplexe Logik in eine eigene ``Methode`` auslagern!

## Warum gibt es Switch überhaupt? (Historischer Hintergrund)
Man könnte sich fragen, warum man `switch` braucht, wenn man doch alles mit `else if` schreiben kann. 

Historisch gesehen wurden ``Switch-Anweisungen`` von ``Compilern`` in sogenannte *Jump Tables* (Sprungtabellen) übersetzt. Bei einer langen Kette von `else if`-Abfragen muss der Computer jede einzelne ``Bedingung`` von oben nach unten berechnen, bis eine zutrifft. Bei einer *Jump Table* nutzt der Compiler den konkreten Wert (den ``Schlüssel``) als Index, um *direkt* an die richtige Stelle im Code zu springen – ganz ohne Bedingungen auszurechnen.

Deshalb war die ``Switch-Anweisung`` früher strikt auf ``Typen`` beschränkt, die klare, abzählbare Werte haben (`int`, `char`, `string`, `enum`). 

Wir merken uns jedoch:
> Wir verwenden ``Switch-Verzweigungen`` in der Praxis **nicht**, weil wir glauben, den Code damit "schneller" zu machen, sondern immer dann, wenn der Code dadurch **besser lesbar** wird!

*(Anmerkung: Modernes C# unterstützt in `switch` mittlerweile mächtiges "Pattern Matching", wodurch man auch Bereiche wie `> 10` abfragen kann. Unter der Haube wird dies dann wie ein `if/else` verarbeitet, bietet aber eine sauberere Syntax).*
